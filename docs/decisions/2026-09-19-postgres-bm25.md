# PostgreSQL BM25 foundation — issue #32

Date: 2026-09-19. Status: implemented and locally validated; pending review and
operator rollout.

## Decision and rationale

The owner approved treating the issue as direction rather than copying its
example SQL. Use pg_textsearch 1.1.0 from the existing first-party PostgreSQL 18
image for true BM25, preserving the future dense/BM25/hybrid thesis comparison.
The issue's example `ts_rank_cd` computes cover-density ranking, not BM25.
It also does not guarantee scores in [0, 1] without normalization.

- Extension reference: https://github.com/timescale/pg_textsearch/tree/v1.1.0
- PostgreSQL ranking: https://www.postgresql.org/docs/18/textsearch-controls.html#TEXTSEARCH-RANKING
- Planning issue: https://github.com/pedro-stanaka/yuussuke-tcc/issues/32

## Differences from the example acceptance criteria

- `chunk_meta`, Alembic, persistent source text, DI, filters, idempotent writes,
  corpus updates, ingestion integration, and backfill are retained.
- A `USING bm25` index replaces the generated `tsvector`/GIN index. No unused
  GIN index is added merely to reproduce an example for another ranking method.
- `public.bula_portuguese` combines the built-in Portuguese configuration with
  `unaccent`. The same configuration is used by the index and query parsing.
  No falsely immutable wrapper around the stable `unaccent()` function is needed.
- Native `<@>` distance is negative BM25. The repository returns its negation,
  filters zero-score nonmatches, and adds chunk_id as a stable tie-breaker.
- Source chunk IDs are not Qdrant point IDs. Existing payloads lack `doc_id`;
  document identity is derived from the verified bula UUID, matching ingestion.
- Production lexical persistence has no SQLite dependency. Existing unrelated
  test fixtures still use SQLite; removing them is not part of this feature.

## Consistency and security

Routers are unchanged. The index service delegates SQL to a repository; services
do not access the session directly. Chunk rows reference bulas with delete cascade.
Upserts cannot transfer an existing chunk identity to another bula. Replacement
and stale-row deletion are atomic per bula; the worker marks ready only after
both Qdrant and PostgreSQL succeed. Retry is idempotent but is not a distributed
transaction. Existing ready documents require an explicit operator backfill.

Backfill validates a complete document before replacing it, commits per bula,
uses current relational corpus/name, and never calls parsing/embedding models.
Run it with ingestion and corpus mutations paused. It does not correct stale
content already present in Qdrant. Partial multi-bula completion is resumable.

The index is an internal data access facility, NOT an authorization layer. Future
retrievers must authorize selected bulas and apply publication/ownership policy;
`corpus=private` by itself never authorizes another user's content.

## Known limitations and #55 handoff

- pg_textsearch 1.1.0 documents post-filtered top-k behavior. Queries materialize
  eligible rows before scoring so a restrictive bula/corpus filter cannot lose
  matches to unrelated documents. This prioritizes exact filtered results over
  index-only top-k speed; benchmark before using broad cross-corpus searches at
  scale. BM25 statistics remain those of the shared index, not per-bula statistics.
- Portuguese stemming plus accent folding is not morphological equivalence for
  every word. Verified example: `paciente` finds `pacientes`, and `sodica` finds
  `SÓDICA`; however `contraindicação` and `contraindicações` become different stems
  after accent folding (`contraindicaca` / `contraindicaco`). Do not promise the
  latter assertion from #55 without a separately tested normalization decision.
- BM25 scores are not calibrated relevance probabilities. RRF should use ranks,
  not assume compatible score scales across dense and lexical retrieval.
- This does not implement the LangChain sparse retriever, hybrid fusion, mode
  selection, UI controls, or clinical answer evaluation (#55–#57, #51, #75).

## Validation approach

Use isolated PostgreSQL with the exact first-party image and real extension.
Cover migrations, accents/stemming, no matches/stopwords, top-k, filters, score
order, upsert persistence across sessions, cross-bula collisions, rollback,
replacement, corpus changes, deletion cascade, and parameterized queries.
Backfill integration uses Qdrant's real client in local mode plus PostgreSQL.
Unit tests cover worker-path failure before ready, retry, source validation,
dry-run, CLI errors, and pagination. No production corpus was migrated or copied
while developing this change.
